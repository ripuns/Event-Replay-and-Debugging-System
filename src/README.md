# src

Application root. Bootstraps the NestJS process and wires the top-level module tree.

## Files

| File | Purpose | Why |
|---|---|---|
| `main.ts` | Application entrypoint: creates the Nest app, applies the global `ValidationPipe` (whitelist + transform) and `AllExceptionsFilter`, registers graceful shutdown on `SIGINT`/`SIGTERM`, sets the global route prefix `/v1`, mounts Swagger (`@nestjs/swagger`) at `v1/docs` with a bearer (`api-key`) auth scheme, and starts listening on `PORT`. | Centralizes cross-cutting HTTP concerns (validation, error shape, shutdown, versioned prefix, API docs) in one place instead of scattering them across modules. Swagger is set up after `setGlobalPrefix` so its documented paths match the real `/v1/...` routes. |
| `app.module.ts` | Root Nest module. Loads and validates env config (`DATABASE_URL`, `REDIS_URL`, `JWT_SECRET` required; `PORT` defaulted) via `ConfigModule.forRoot`, and imports `HealthModule`, `AuthModule`, `ProjectsModule`, `OrganizationModule`, `EventsModule`, `EventReducersModule`, `AggregatesModule`, `SnapshotsModule`, `ReplayJobsModule`. | Fails fast at boot if required env vars are missing, and is the single place that declares which feature modules exist in the app. Does not import `PrismaModule` directly — it's `@Global()` (see `prisma/README.md`), so every feature module that needs it imports it itself. |

## Subfolders

| Folder | Purpose |
|---|---|
| `modules/health` | Liveness/status endpoint. |
| `common/auth` | Authentication guards and request-context types (API-key auth is the active mechanism; JWT scaffolding exists but is unused — see that folder's README). |
| `common/filters` | Global exception normalization (including server-side logging of unexpected 500s). |
| `config` | Typed env-var loaders consumed by `ConfigModule`. |
| `prisma` | Nest wrapper around the Prisma client (DI-friendly `$connect`/`$disconnect`). |
| `organization`, `projects`, `api-keys` | Domain modules — organizations own projects, projects own API keys, following the architecture in `CONTEXT_SUMMARY.md`. |
| `events` | Event append API (Phase 5) — the append-only event store write path, with server-assigned per-aggregate sequence numbers; also triggers async snapshot creation (Phase 6) when an aggregate crosses the snapshot threshold. |
| `event-reducers` | Declarative per-`aggregateType`+`eventType` config for how an event folds into aggregate state (Phase 5) — consumed by `aggregates` during reconstruction. |
| `aggregates` | Aggregate state reconstruction (Phase 5) — replays an aggregate's events (optionally up to a given sequence number, for time-travel debugging) and folds them via `event-reducers` config, starting from the nearest snapshot when one exists (Phase 6). |
| `queues` | Shared BullMQ/Redis queue infrastructure (Phase 6) — the queue names and root `BullModule` config consumed by `snapshots` and `replay-jobs`. |
| `snapshots` | Async, queue-backed snapshot creation (Phase 6) — the performance optimization behind `aggregates`' reconstruction speed. |
| `replay-jobs` | Bulk/async aggregate reconstruction across many aggregates at once (Phase 6), tracked as a pollable job. Closes out Phase 6. |
| `cache` | Redis-backed application-level caching (Phase 7) — full reconstructed-state and snapshot-lookup caches for `aggregates`, invalidated by `events`/`snapshots` whenever new data lands. |
| `generated/prisma` | Auto-generated by `prisma generate` — never hand-edited, no README (regenerate instead of documenting drift). |
