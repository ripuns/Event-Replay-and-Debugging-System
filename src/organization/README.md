# src/organization

Organization domain module — the top-level tenant boundary. An organization owns projects (see `../projects`).

## Files

| File | Purpose | Why |
|---|---|---|
| `organization.controller.ts` (`OrganizationController`) | `POST /v1/organizations` — unauthenticated (bootstrapping problem: no key can exist before an org does). Accepts `{ name, firstProject?: { name } }`; if `firstProject` is given, atomically creates the org, that project, and its first API key in one response — collapsing the org→project→key three-hop bootstrap into a single call. `GET /v1/organizations/:id` — guarded by `ApiKeyGuard`, then manually checks `request.auth.organizationId === :id` (no separate `OrganizationAccessGuard` needed here since it's a same-resource check, not a nested-route check). | Thin controller: all creation/lookup logic lives in `OrganizationService`; the controller only validates input (via DTO) and enforces the org-id-matches-key check before returning data. |
| `organization.module.ts` (`OrganizationModule`) | Imports `PrismaModule`, `ApiKeyModule`, `ProjectsModule`; provides `OrganizationService`/`OrganizationRepository`/`ApiKeyGuard`; registers `OrganizationController`; exports `OrganizationService`. | Imports `ProjectsModule` (rather than duplicating a `ProjectsRepository` provider) because the bootstrap flow needs to create a project as part of organization creation — one-way dependency, no cycle (`ProjectsModule` never imports `OrganizationModule`). |
| `organization.service.ts` (`OrganizationService`) | `create(name, firstProject?)`: without `firstProject`, just creates the org; with it, wraps org+project+key creation in `prisma.$transaction(...)` so all three succeed or none do. `findById(id)`. | The transactional path exists so a crash mid-bootstrap (e.g. key generation fails) can never leave an org with no usable credential, or a project with no org. |
| `organization.repository.ts` (`OrganizationRepository`) | Thin Prisma wrapper: `create(name, client?)`, `findById(id)`. Accepts an optional Prisma client/transaction param (defaults to the injected `PrismaService`) so `create` can run inside the service's transaction. | Keeps direct Prisma query syntax out of the service layer, consistent with `projects/` and `api-keys/`. |
| `dto/create-organization.dto.ts` (`CreateOrganizationDto`) | `class-validator` DTO: `name` (required string, max 255) plus an optional nested `firstProject: { name }` (validated via `@ValidateNested`/`@Type`). | Nested validation so a malformed `firstProject` object is rejected by the global `ValidationPipe` before it ever reaches the service. |
